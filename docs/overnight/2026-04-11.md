## Research Findings

### Django Updates & Deprecations

**Django 5.2 LTS** (April 2025): composite primary keys, improved `values()`/`values_list()` with `union()`, automatic shell imports. **Django 6.0** (December 2025): built-in background tasks (Celery alternative — relevant for VCF import), template partials, native CSP support.

**Deprecation check:** None of MetaGap's APIs are deprecated. `models.JSONField`, `gettext_lazy`, `LoginRequiredMixin`, `OneToOneField`, `TextChoices`, `UniqueConstraint` are all safe and current.

**Warning:** Django 6.0 drops Python 3.10 and 3.11. MetaGap targets Python 3.11, so a 6.0 upgrade requires moving to Python 3.12+. Recommended path: 5.1 → 5.2 LTS first.

### VCF/Genomics Horizon

**VCF 4.4 is published** (samtools hts-specs) with new fields: LGT (local genotype), LPL (local Phred-scaled likelihoods), improved structural variant representation. **Draft VCF 4.5** is in progress with modified base representation.

These new header fields would currently land in `additional_metadata` as unmapped keys — not a breakage, but a data loss risk for labs generating VCF 4.4 output.

**pysam 0.23.3** wraps htslib 1.23.1 which natively parses VCF 4.4. Upgrading pysam brings compatibility without code changes. **vcfpy 0.14.2** only officially supports VCF 4.3 — risk if VCF 4.4 files arrive. **cyvcf2** remains a high-performance alternative but would be a larger migration.

### CI Gaps

Current pipeline (`ci.yml`) analysis:

| Issue | Impact | Fix |
|-------|--------|-----|
| **No linting** (ruff/flake8/mypy) | Style drift, type bugs slip through | Add `ruff check` step |

## Suggestions

Ranked by estimated value:

1. **Upgrade Django to 5.2 LTS immediately** — 15+ CVEs including SQL injection. This is a security emergency. Run `python -Wa manage.py test` first to surface deprecation warnings, then bump version. Estimated effort: 1-2 hours.

2. **Add `pip-audit` to CI** — would have caught the Django CVEs months ago. One step addition, ~5 minutes to implement.

3. **Add `ruff` linting to CI** — catches unused imports (like `settings` in models.py), style inconsistencies, and common bugs. Quick win.

4. **Bump pysam to 0.23.3** — gains VCF 4.4 support, Python 3.13 compatibility, and htslib 1.23.1. Low risk, high future-proofing value.

5. **Add VCF 4.4 field mappings to `metadata_fields.yaml`** — LGT, LPL, and new SV fields would be correctly parsed instead of dumped to additional_metadata.

6. **Fix or remove `get_or_create_sample_group()`** — uses non-existent model fields (`description`, `organization_profile`). Either fix to use `comments`/`created_by` or remove if unused in production.

7. **Add CI pip caching and Python 3.12 matrix** — faster runs and broader compatibility testing for eventual Django 6.0 migration.

8. **Add tests for VCF import error paths** — corrupt gzip, duplicate variants, empty VCF files. These are the most likely real-world failure modes.
