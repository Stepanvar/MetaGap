## Research Findings

### Django Updates & Deprecations

- **Django 5.2 is an LTS release** (April 2, 2025; supported through April 2028). Safe upgrade target for this project.
- New features: composite primary keys (potential future use for AlleleFrequency), automatic model imports in shell, `response.text` convenience property.
- **No deprecation impact** on MetaGap patterns: `LoginRequiredMixin`, `gettext_lazy`, `models.JSONField`, `i18n_patterns`, signals, CBVs all remain stable in 5.2.
- Django 6.0 requires Python >= 3.12 (MetaGap uses 3.11), so **5.2 LTS is the correct target**.

### VCF/Genomics Horizon

- **VCF spec remains at v4.3** (maintained by GA4GH via hts-specs). No VCF 4.4 or 4.5 published. Stable.
- **VCF-Zarr**: 2025 GigaScience paper presents Zarr-based encoding for biobank-scale datasets (650K+ samples). Columnar access, better compression, parallel processing. Worth watching for population-scale data.
- **Parsing libraries**: pysam (htslib wrapper) and cyvcf2 (6.9x faster) remain dominant. vcfpy (pure Python, used by MetaGap) is slowest but most portable. **vembrane** is a newer higher-level filtering tool built atop pysam/cyvcf2.
- Current pysam+vcfpy dual approach remains sound. cyvcf2 is the proven upgrade path if performance becomes an issue.

### CI Gaps

1. **Branch mismatch**: CI triggers on `main` but repository default branch is `master`. Pushes to `master` may not trigger CI.
2. **No linting step**: No ruff, flake8, or mypy in CI. Adding `ruff check` as a parallel job would catch style/quality issues.
3. **No security scanning**: No bandit, safety, or pip-audit step. Given the Django CVE situation, automated dependency scanning would surface issues earlier.
4. **No pip caching**: `actions/setup-python@v5` supports pip caching (`cache: 'pip'`), which would speed up dependency installation.
5. **Coverage not pinned**: CI installs `coverage` without a version pin, which could cause reproducibility issues.

### Unused Code

- **Database utility functions** (`convert_to_python_type`, `extract_info_field_metadata`, `extract_format_field_metadata`, `extract_contig_field_metadata`, `get_or_create_sample_group` in vcf_database.py) are only imported by test files, never used in production code. Consider marking them as test helpers or making them private.
- **`Promise` import** in `app/views.py` is used in only one type-check; could be simplified.
- All other imports across views, forms, filters, and tables are actively used.
