## Research Findings

### Django Updates & Deprecations

- **Django 5.1 is EOL since 2025-12-31**; no further security fixes are issued. Django 5.2 (LTS, supported through 2028-04) is the recommended landing point. ([endoflife.date/django](https://endoflife.date/django), [Django 5.2 release notes](https://docs.djangoproject.com/en/6.0/releases/5.2/))
- **Django 6.0 GA shipped 2025-12-03** — *not* an LTS — bringing Template Partials (`{% partialdef %}` / `{% partial %}`), built-in async **Tasks** framework for background work, native CSP support (no more middleware shim), and a modernized Email API (`EmailMessage`-based, Unicode-friendly). These would be incremental wins after the 5.2 jump, not before. ([Django 6.0 release notes](https://docs.djangoproject.com/en/6.0/releases/6.0/), [InfoQ on Django 6.0](https://www.infoq.com/news/2026/01/django-6-release/))
- **2026-04-07 security release** (Django 5.2.13 / 6.0.4 / 4.2.30): three CVE-tier fixes — ASGI now ignores underscore headers (matches Daphne); `GenericInlineModelAdmin` properly validates per-instance add permissions on POST; admin changelist `list_editable` no longer accepts forged POST data to create instances. All low severity but the project misses all three on 5.1.1. ([Django security release](https://www.djangoproject.com/weblog/2026/apr/07/security-releases/))
- **URLField default scheme** has hard-cut to `https` in 6.0; this project does not use `URLField` (only `EmailField`, models + form), so the deprecation does not bite — but flag it for any future URL inputs. ([URLField ticket](https://code.djangoproject.com/ticket/34380))
- `USE_L10N = True` in `settings.py:138` has been a deprecated (no-op) flag since Django 4.0 — `USE_L10N` is permanently `True` in the current codebase. Drop the line.
- The settings module's docstring still references *"Django 2.1.2"* and links to `docs.djangoproject.com/en/2.1/`. Trivial cleanup.

### VCF/Genomics Horizon

- **VCFv4.5** has been the canonical samtools/hts-specs version since 2024-10-09 (`samtools/hts-specs/VCFv4.5.pdf`). 4.4 is officially superseded. Our importer treats `##`-prefixed metadata generically — unmapped sections land in `SampleGroup.additional_metadata`, unmapped INFO/FORMAT keys land in `Info.additional`/`Format.additional` — so 4.5 files won't error. They also won't be *understood*: new reserved INFO keys (e.g., modified-base annotations, haplotype-linkage codes) become anonymous JSON.
- **pysam 0.23.3** wraps htslib 1.23.1, which understands the 4.5 spec; bumping is the cheapest path to "we read 4.5 correctly."
- **vcfpy** PyPI cadence is essentially frozen (last upload >12 months stale). It's only used by `MetagapUserCode/merge_vcf` (not by the Django app's import path), but if cohort-merge ever hits a 4.5-only header we'll need a fallback strategy.
