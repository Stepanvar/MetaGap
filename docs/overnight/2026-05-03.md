## Research Findings

### Django Updates & Deprecations

- **Django 5.2 (LTS to 2028-04)** — drop-in for 5.1 in this codebase aside from the deprecations below. Notable wins:
  - `CompositePrimaryKey` could in principle replace `AlleleFrequency.UniqueConstraint(sample_group, chrom, pos, ref, alt)`, but admin/FK-target support is not yet there — defer.
  - `BoundField`/`bound_field_class` customization could simplify `BootstrapFormMixin` (`forms.py`) — directly tag widgets at field-level instead of post-hoc.
  - `manage.py shell` auto-imports models — minor DX win.
  - `Response.text` property — could shorten test assertions.
- **Deprecations relevant**: `staticfiles.finders.find(all=...)` → `find_all=`; `postgres.aggregates` `ordering=` → `order_by=`. **Neither used in this code** (grep clean) — safe upgrade.

### VCF/Genomics Horizon

- **VCF 4.4 not yet finalized** (Oct 2024 draft is current). Active milestone with open structural-variant issues (#544) and meta-issues (#640). Treat as draft — no schema changes needed yet.
- **2026 ecosystem**: cyvcf2 still ~7× faster than pysam for read-heavy paths; vembrane for filter/transform with Python expressions; pygenomics for pure-Python no-deps. No dominant new entrant. Current pysam→fallback architecture is fine.

### CI Gaps

`MetaGap/.github/workflows/ci.yml` runs only test+coverage. Missing:
- **No linting step** (no `ruff`, `flake8`, `black`, `isort` in CI or `requirements.txt`).
- **No type-checking** (no `mypy`/`pyright`) — `vcf_database.py` is heavily type-annotated, no enforcement.
- **No security scan** (no `pip-audit`, `safety`, `bandit`) — would have caught Django/urllib3/requests CVEs.
- **No `pytest` invocation** — directly causes the 170 orphaned tests problem above.
- **`pip install -r requirements.txt coverage` unpinned `coverage`** — CI non-determinism.
- **CI runs on `main` push and PRs only** — no weekly/scheduled run, so dependency CVEs don't surface until next push.

### Unused Code

- **`app/services/vcf_database.py:188-217`** — `get_or_create_sample_group()`: docstring says "simplified helper for testing"; references nonexistent fields `description=` and `organization_profile=`; bare `except` returns `None`. Only callers are the orphan tests in `test_vcf_database.py`. **Delete.**
- **`app/services/vcf_database.py:115-185`** — `extract_info_field_metadata`, `extract_format_field_metadata`, `extract_contig_field_metadata`: only consumers are orphan tests; production code uses `pysam` header records directly. **Delete or wire into the importer.**
- **`app/services/vcf_database.py:68-112`** — `convert_to_python_type`: same — orphan-test-only. The class methods `_coerce_info_value` / `_normalize_info_scalar` cover the live path.
- **`app/services/vcf_metadata.py:215-366`** — `METADATA_MODEL_MAP`, `METADATA_FIELD_ALIASES`, `SECTION_PRIMARY_FIELD` module-level dicts are duplicates of YAML config; only `METADATA_SECTION_MAP` is imported elsewhere (by `vcf_file_utils.py`). The other three (~120 LOC) are dead. **Delete or, better, derive `METADATA_SECTION_MAP` from `load_metadata_configuration()` to remove all duplication.**
- **`app/services/vcf_importer.py:110-112`** — `cleanup_pysam_sample_group()` followed by `if sample_group is not None: sample_group.delete()`. The cleanup just nulled the variable, so the second branch is unreachable. **Dead defensive code.**
- **Unreachable type imports** — `vcf_file_utils.py` declares `Tuple` in return annotations at lines 265, 280 without importing `Tuple` from `typing`. Works only because `from __future__ import annotations` defers evaluation. Add explicit import for type-checker correctness.

Beyond the 170-orphan finding:

## Suggestions

1. **Wire `pytest` into CI and decide the fate of orphan tests.** Either (a) re-skin them as `TestCase` classes so the Django runner picks them up, or (b) add `pytest-django` + a CI step running `pytest app/tests/`. Right now ~170 tests masquerade as coverage. Highest payoff item; will surface real bugs in the broken-API tests on first run. Estimated effort: 2–3 h triage + per-file fixes.
2. **Upgrade Django 5.1.1 → 5.2.13 LTS.** Active CVEs + EOL. Drop-in upgrade for this code (no deprecations triggered). 30 min + full test run.
3. **Bump `urllib3` to 2.5.x and `requests` to 2.32.5.** CVE-2026-21441 (high) and CVE-2026-25645. 5 min.
4. **Add a security-scan + lint job to CI.** Three low-friction tools: `pip-audit` (CVE check), `ruff check` (lint), `bandit -r app/` (security smell). Run as separate non-blocking job initially. ~1 h to wire.
5. **Delete dead code in `vcf_database.py` and `vcf_metadata.py`.** ~150 LOC including the orphan-test-only helpers and the duplicate constant dicts. Removes the temptation to keep two sources of truth for metadata. 1 h including test re-run.
6. **Refresh `app/locale/ru/django.po` (3 missing strings) and run `compilemessages`** so Russian users see the dashboard hero copy and unsupported-file-type error in their language. 15 min.
7. **Pin `coverage` in `requirements.txt`** (e.g., `coverage==7.6.10`) to make CI runs reproducible.
8. **Add a regression test for the `OrganizationSampleGroupMixin` denial path** (cross-org GET → 404/403). Single test; hardens the access-control surface that the suite currently only positively asserts.
