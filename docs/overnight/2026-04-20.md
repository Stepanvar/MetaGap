**Static audit of tests reveals real issues:**

- `app/tests/test_vcf_database.py` is **pytest-style** (`pytestmark = pytest.mark.django_db`, free functions — no `TestCase` subclass). Django's `manage.py test` runner discovers only `unittest.TestCase` descendants, so these tests are silently skipped. No pytest step in CI → file never runs.

## Research Findings

### Django Updates & Deprecations

- **Django 5.1 EOL 2025-12-31** — no further patches. Upgrading to **5.2 LTS** (supported until April 2028) is the minimum safe target.
- Django 5.2 headline features potentially useful here: automatic model imports in shell (dev QoL for this app's 13-model metadata zoo); simplified BoundField customization (would fit `BootstrapFormMixin` — could reduce the per-field widget class-injection dance); composite primary keys (not needed now, but could simplify the `AlleleFrequency` unique constraint on 5 fields in future).
- Django 6.0 removals: `Prefetch.get_current_queryset()`, `get_prefetch_queryset()`, `get_joining_columns()`, positional args to `Model.save()/asave()`, `BaseDatabaseOperations.field_cast_sql()`. Grep the codebase for any of these before upgrading past 5.2.
- `SEQUENCING_PLATFORM_FIELDS` and `PLATFORM_FIELD_MAP` on `SampleGroup` could be simplified with Django 5.0+ `GeneratedField` if any computed platform-active flag is added later.

### VCF/Genomics Horizon

- Community has matured around VCF 4.4 (BCFv2.2) as the current practical target (samtools/hts-specs). Project's fixtures use `##fileformat=VCFv4.2` — still valid, still universal. No urgent migration.
- Known pain points the community is converging on but no replacement yet: single-reference bias, redundancy, no nested/complex variant representation (references: vcflib, cyvcf2, slivar, hts-nim papers). Long-tail concern, not actionable.
- pysam 0.23.3 enhancements relevant here: `AlignedSegment.query_qualities_str` (irrelevant — we don't process BAM), improved `VariantFile` error messages (would tighten the fallback-trigger path in `_should_retry_with_inflated_copy`), musllinux wheels (helps container builds).
- No authoritative VCF 4.5 spec found — treat as not-yet-released.

### CI Gaps

- **No linting** (ruff/flake8/black). 380+-test suite and 13-model schema deserve at least ruff + a `python -m compileall` step.
- **No security scan** — `pip-audit` or `safety check` would have flagged the Django 5.1 EOL automatically. `bandit` would catch `pysam.VariantFile(file_path)` / path-traversal concerns in `_inflate_gzip_to_temp`.
- **No dependency update automation** — Dependabot/Renovate not configured in `.github/`.
- **No pytest step** — pytest is in `requirements.txt` but CI runs `manage.py test`. This is why `test_vcf_database.py` silently skips (see above).
- `coverage report --fail-under=75` for MetagapUserCode is **silently waived** when no relevant modules are collected (line 56 `grep -q "No data to report."`). If a refactor accidentally stops importing MetagapUserCode in tests, coverage regression is masked.
- CI triggers only on `push: branches: [main]` and `pull_request:` — no scheduled run, so an unreleased CVE won't auto-surface until the next push. A weekly `schedule:` cron for `pip-audit` is cheap insurance.
- No `django-admin check --deploy` step — would catch production-config drift (SECRET_KEY, SECURE_SSL_REDIRECT, etc.).
- `compilemessages` not exercised in CI. `test_locale_compiler.py` exists but check CI path covers it.
- `actions/setup-python@v5` does not cache pip by default for this workflow — add `cache: pip` to trim ~30s per run.

### Unused Code

- `app/services/vcf_database.py::get_or_create_sample_group` (lines 188-217) — referenced only in the orphaned `test_vcf_database.py`. Uses fields that don't exist on `SampleGroup` (`description`, `organization_profile`). Exception-swallowing (bare `except Exception`) hides the bug. **Delete.**
- `app/services/vcf_database.py::convert_to_python_type`, `extract_info_field_metadata`, `extract_format_field_metadata`, `extract_contig_field_metadata` — all module-level helpers exported only via `__all__` and imported only by the orphaned pytest file. If the pytest file is kept, they're fine; if the test file is deleted, so should these. Current state: 5 exported helpers kept alive solely to satisfy 5 skipped tests.
- `vcf_metadata.py` contains hardcoded `METADATA_*_MAP` dicts (lines 183-366) mirroring the YAML. Only `METADATA_SECTION_MAP` is imported externally (by `vcf_file_utils.py`). The other three hardcoded dicts (`METADATA_MODEL_MAP`, `METADATA_FIELD_ALIASES`, `SECTION_PRIMARY_FIELD`) are unused — delete and keep the YAML-driven `load_metadata_configuration()` as the single source of truth.
- `vcf_file_utils.py` line 265 declares `-> Iterable[Tuple[str, Dict[str, Any]]]` but `Tuple` is not imported. Safe at runtime thanks to `from __future__ import annotations`, but type checkers will flag.

### Test Quality Notes

- `test_vcf_database.py` is the biggest red flag — pytest-only, undiscovered, asserts against non-existent attributes. Either (a) convert to `TestCase`, (b) add pytest to CI, or (c) delete the file and the dead helpers it tests.
- Happy-path skew: `test_vcf_importer.VCFImporterTests` has strong coverage of well-formed inputs and most alias scenarios. Light on: truncated `#CHROM` line with fewer than 8 fields (warning path in `parse_vcf_text_fallback`), VCF with only `#CHROM` header and no data (missing-header path), gzip file that is corrupt mid-stream (inflate failure cleanup).
- `Info._normalize_placeholder_values` branch where `self.additional` is a non-dict — early return, untested.
- `SampleGroup._match_platform_candidate` substring-match (`alias in normalized_candidate`) could cause false positives (`ion` substring matches `iontorrent_seq`). Edge-case test for e.g. `"Ion Proton"` vs `"Nanopore Ion-preserved"` would be valuable.
- Form/view access-control tests (`test_views_sample_group_access.py`, `OrganizationSampleGroupMixin`) — verify they hit the 403/404 branches, not just happy path.

## Suggestions

Ranked by estimated value.

1. **Upgrade Django 5.1.1 → 5.2 LTS (then 5.2.13).** Highest priority — 5.1 is EOL and at least 5 publicly-known 2026 CVEs exist. Read 5.2 release notes for `QuerySet.values()` SELECT-order change (may affect search/export queries), and test `BootstrapFormMixin` against new BoundField behaviour.
2. **Delete `get_or_create_sample_group` and the orphaned `test_vcf_database.py` (or convert to `TestCase`).** Either direction removes a latent bug. Decide based on whether pytest will be added to CI.
3. **Add a pytest step to CI**, or add explicit `django.test.TestCase` shims. If kept as pytest-only, also add `pytest-django` and a second CI step `python -m pytest`. Configures `manage.py test` + `pytest` side-by-side per Django docs.
4. **Bump django-allauth to ≥65.14.3** for SAML RelayState + rate-limit CVEs. Low-risk; 65.x line is semver-stable.
5. **Bump gunicorn to 25.3.0** for CVE-2025-47287 (HTTP request smuggling).
6. **Bump pysam to 0.23.3** for better `VariantFile` error messaging and musllinux wheels (faster container builds).
7. **Add `pip-audit` or `safety` + `ruff check` as CI steps.** One job, ~20s, catches exactly the class of problem above. Add `cache: pip` to setup-python for another 30s shaved.
8. **Single-source the metadata config.** Delete hardcoded `METADATA_MODEL_MAP`, `METADATA_FIELD_ALIASES`, `SECTION_PRIMARY_FIELD` in `vcf_metadata.py` (lines 215-366); have `vcf_file_utils.py` obtain `METADATA_SECTION_MAP` via `load_metadata_configuration().section_map` instead.
