## Research Findings

### Django Updates & Deprecations

- **Django 5.2 LTS (released 2025-04-02, supported to April 2028)** is the correct upgrade target from 5.1. Worth doing before touching anything else.
- 5.2 headline features potentially useful here:
  - Automatic model imports in `python manage.py shell` — QoL with 13+ metadata models.
  - Composite primary keys — future option if `AlleleFrequency`'s 5-field unique constraint grows.
  - `HttpRequest.accepted_types` sorted by client preference — minor, but useful if content-negotiation is added to export endpoints.
  - `Model._is_pk_set()` — useful in `SampleGroup.delete()` selective cleanup to tighten the pre-delete guards.
- Deprecations to watch for this codebase when moving past 5.2:
  - `all=` → `find_all=` on `django.contrib.staticfiles.finders.find()` (whitenoise territory).
  - Fallbacks to `request.user` / `request.auser()` when `user is None` in `auth.login`/`auth.alogin` — check the django-allauth upgrade path.
  - `ArrayAgg`/`JSONBAgg`/`StringAgg`'s `ordering=` → `order_by=` — doesn't appear to be used in this codebase but grep before upgrade.
  - MySQL defaults to `utf8mb4` — irrelevant (sqlite dev, pg prod likely).
- Django 6.0 removals to audit before going past 5.2: `Prefetch.get_current_queryset()`, `get_prefetch_queryset()`, `get_joining_columns()`, positional args to `Model.save()/asave()`, `BaseDatabaseOperations.field_cast_sql()`. None obviously used here.

### VCF/Genomics Horizon

- VCF 4.4 (BCFv2.2) remains the practical target (samtools/hts-specs). Project fixtures are `VCFv4.2` — still universal. No urgent migration.
- Draft VCF 4.5 is discussed but not released; it recommends VCF libraries provide an API for value access (a change for library authors, not consumers).
- GA4GH (not 1000 Genomes) is the current steward of the spec.
- pysam 0.23.3 improvements relevant here: tighter `VariantFile` error messages (would let `_should_retry_with_inflated_copy` match fewer false-positives), musllinux wheels (container build speed), GT-reset bugfix (would affect `create_format_instance` serialization if the codebase ever reuses `VariantHeader.new_record`).
- Scalable VCF alternatives worth a backlog note: community interest in sparse/population-scale representations (see Oxford Academic 2025 paper on "scalable variant call representation"). Not actionable for current scale, but tag for future `AlleleFrequency` table scaling concerns.

### CI Gaps

- **Major: 170 of 320 tests never run in CI** (pytest-style free functions + missing `pytest-django`). CI runs `python -m coverage run manage.py test` which does unittest-only discovery. Yesterday's report noted the `test_vcf_database.py` case; the real scope is 7 files.
- **Coverage not in `requirements.txt`** — installed inline in CI (`pip install -r requirements.txt coverage`). Locks CI to a floating coverage version. Pin it.
- No linting step (ruff/flake8/black). A 320-function test tree + 13-model schema deserves at least `ruff check`.
- No security scan (`pip-audit` / `safety`) — would have auto-flagged the 5.1 EOL and allauth CVEs.
- No dependency update automation — Dependabot/Renovate not configured.
- The `coverage report --fail-under=75` for MetagapUserCode is **silently waived** when "No data to report." is matched (ci.yml:56). If a refactor accidentally stops exercising MetagapUserCode, coverage regression is masked.
- CI triggers are `push: main` + PRs only — no `schedule:` cron, so CVE auto-surfacing only happens when someone pushes.
- `actions/setup-python@v5` lacks `cache: pip` — ~30 s/run lost.
- No `django-admin check --deploy` step — prod-config drift (SECRET_KEY, SECURE_SSL_REDIRECT, etc.) would slip through.
- The `Annotate metadata warnings` step (ci.yml:66-77) greps `test-output.log` for "Unhandled metadata key" — but none of the "Unsupported sequencing platform" / "Could not parse VCF metadata with pysam" warnings we see in the test run match the grep. The annotator misses most of the warning traffic the suite emits.

### Test Quality Notes

- **Pytest-only files (170 tests) are a latent liability**: tests exist, import correctly, and look thorough on paper — but are silently absent from every CI run. Some (`test_locale_compiler.py`, 22 tests) pass when run under pytest standalone; others (`test_filters.py`, 27 tests) can't even collect without `pytest-django`. CI green is not a signal of correctness for the areas those files cover.
- Happy-path skew in the unittest tests remains: `test_vcf_importer.VCFImporterTests` exercises well-formed VCFs heavily; truncated-line, no-data, corrupt-mid-gzip, and missing-`#CHROM` paths are light.
- Demo-data test (`test_demo_data_import.py`, 3 tests) is thin for the breadth of `app/fixtures/demo_data.json` — consider adding assertions about OrganizationProfile signal wiring and fixture-level constraint integrity.
- Access-control tests (`test_views_sample_group_access.py`, 17 tests / 2 TestCase classes) were presumably written to exercise 403/404 branches — worth a quick re-read to confirm both permit and deny paths are asserted (not just the permit path).

## Suggestions

Ranked by estimated value.

1. **Fix the CI test-discovery gap.** Two options:
   (a) Convert the 7 pytest-only files to `django.test.TestCase` subclasses (largest surface, but keeps CI consistent with the `manage.py test` invocation), or
   (b) Add `pytest-django` to `requirements.txt` and a second CI step `python -m pytest app/tests MetagapUserCode/tests`. This also lights up the MetagapUserCode pytest suite, which is currently outside the Django runner.
   Either way, the 170 hidden tests become visible before a regression lands.
2. **Upgrade Django 5.1.1 → 5.2 LTS (then latest 5.2.x).** 5.1 EOL'd 2025-12-31; multiple 2026 CVEs (SQL injection in `FilteredRelation` on PG; XML serializer DoS; header-spoofing; DATA_UPLOAD bypass) have no backport.
3. **Bump django-allauth to ≥65.14.3** — SAML RelayState open-redirect + rate-limit-bypass CVEs. Low-risk within 65.x.
4. **Bump gunicorn** to address CVE-2025-47287 (HTTP request smuggling).
5. **Delete `get_or_create_sample_group` + the four orphan helpers** in `vcf_database.py`, or (if path 1 adds pytest) fix the broken test assertions and matching helper signatures.
6. **Pin `coverage` in `requirements.txt`** (or a `requirements-dev.txt`). Today's local `metagap-py311` env had no coverage binary; CI only has it because it `pip install`s mid-workflow, so local-vs-CI semantics diverge.
7. **Add `ruff check` + `pip-audit` CI steps**, plus `cache: pip` on `setup-python@v5`. ~1 extra minute, catches the class of issues this report keeps surfacing.
8. **Translate the two outstanding `MetaGap/locale/en` msgids.** Trivial cleanup, zero risk.
9. **Commit the accumulated `docs/overnight/2026-04-{11,12,14,17,18,19,20}.md` reports.** They've been produced by the nightly agent but never committed — check whether the commit step ever ran and, if not, fix the harness or manually land them.
10. **Single-source the metadata configuration.** Delete the hardcoded `METADATA_MODEL_MAP`, `METADATA_FIELD_ALIASES`, `SECTION_PRIMARY_FIELD` in `vcf_metadata.py` (lines 215-366); change `vcf_file_utils.py` to obtain `METADATA_SECTION_MAP` via `load_metadata_configuration().section_map`.
