## Research Findings

### Django Updates & Deprecations

- **Upgrade target: Django 5.2 LTS (`5.2.13`).** Same one-line bump recommended for 6 consecutive reports. Low migration risk for this codebase — ORM, class-based views, `i18n_patterns`, `gettext_lazy`, `SET_NULL` FKs, `JSONField`, and `transaction.atomic()` are all unchanged. Python 3.11 stays supported on 5.2; moving to 6.0 would require Python 3.12+.
- **6.0-track features not yet adopted:** first-party CSP (`django.middleware.csp.ContentSecurityPolicyMiddleware`), background tasks framework, `AsyncPaginator` / `AsyncPage`, modernized `EmailMessage`. All optional.
- **Deprecations in use? No.** The `SampleGroup.delete(using, keep_parents)` positional-arg call (`models.py:595`) is unaffected (the positional-arg removal targets `Model.save`/`asave`). `URLField` default-scheme http→https is a 6.0 change, not 5.2.

### VCF / Genomics Horizon

- **VCF 4.5 draft** (hts-specs) is still the open frontier. It adds modified-base information to the genotype record. Existing 4.2/4.3 VCFs remain valid; the importer requires no change unless the project chooses to accept 4.5-specific annotations.
- **pysam 0.23.3** wraps `htslib 1.21`; `bcftools` 1.21. The upgrade is purely maintenance. `VariantFile.fetch()` / `record.info` / `record.samples` APIs used in `vcf_importer.py:161-179` are unchanged.
- **vcfpy 0.14.2** remains the current release; no 1.x in sight.

### CI Gaps

Re-verified from `.github/workflows/ci.yml`:

- **Branch trigger mismatch — still not fixed.** `on.push.branches: [main]` at line 5–6; repository default branch is `master`. `master` pushes never trigger CI. Either rename the branch (`git branch -m master main` and update origin) or add `master` to the trigger list.
- **Runs only unittest** (line 36). Pytest-style tests remain invisible — see Test Status section.
- **No lint step.** No `ruff check`, `flake8`, `black --check`, or `isort --check`. A `ruff check app MetagapUserCode MetaGap` job takes <5 s and would have caught the unused `GENERIC_FALLBACK_VALIDATION_MESSAGE` import listed below.
- **No security scan.** No `pip-audit` step. Given Django 5.1.1 is EOL with public CVEs, `pip-audit -r requirements.txt` would have flagged the issue 6+ months ago.
- **No `compilemessages` verification.** A broken `.po` catalog could ship without CI failure.
- **`coverage` installed unpinned** (line 29: `pip install -r requirements.txt coverage`). Minor, but can produce surprise behavior differences. Pin to a specific major.
- **Python 3.11 hard-coded** (line 24). Matrix build against 3.11 + 3.12 would prepare for the Django 6.0 / Python 3.12 window.
