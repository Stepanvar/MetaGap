### Django Security Detail (carry-forward from prior reports + April 2026 update)

Django 5.1 has been EOL since **2025-12-31** — no further security patches. Vulnerabilities patched in 5.2.x but **unpatched in 5.1.1**:

- **CVE-2026-25673** — `URLField.to_python()` DoS via slow NFKC normalization on Windows.
- **CVE-2026-25674** — Race condition in file-system storage/cache backends.
- **CVE-2026-3902** — ASGI header-name normalization (underscore/hyphen confusion → header spoofing).
- **CVE-2026-33034** — ASGI missing Content-Length bypass → unbounded memory.
- SQL injection via crafted dict expansion into `QuerySet.filter()`/`Q()` (2025-11).
- SQL injection in `FilteredRelation` column aliases on PostgreSQL (2025-12).
- DoS via XML serialization complexity (2025-12).
- Further issues shipped in 5.2.11 (2026-02-03), 5.2.12 (2026-03-03), 5.2.13 (2026-04-07) — admin form validation, ASGIRequest header handling, user enumeration.

**Recommended upgrade target: Django 5.2.13.** 5.2 is LTS (supported through 2028-04) and supports Python 3.10/3.11 (MetaGap runs 3.11). Django 6.0 requires Python ≥ 3.12 and is therefore not yet suitable without a Python upgrade.

## Research Findings

### Django Updates & Deprecations

Django 5.2 LTS is a safe upgrade path for this project. Relevant notes if a 5.1 → 5.2 upgrade lands:

- **Composite primary keys** — a potential future simplification for `AlleleFrequency`'s `(sample_group, chrom, pos, ref, alt)` unique constraint.
- **Automatic model imports in `shell`** — quality-of-life improvement for debugging.
- **`response.text` property** — convenience addition, no migration needed.
- No MetaGap-used API is deprecated in 5.2: `LoginRequiredMixin`, `gettext_lazy`, `models.JSONField`, `i18n_patterns`, signals, CBVs, `ForeignKey(on_delete=SET_NULL/CASCADE)`, and `OneToOneField` all remain supported.

Django 6.0 (October 2025) is *not yet* a target because MetaGap runs Python 3.11 and 6.0 requires Python ≥ 3.12. Forward-looking items that would eventually matter on a 6.0 upgrade:

- Built-in CSP header support.
- Native background-tasks framework (could eventually replace any need for Celery in VCF imports).
- `AsyncPaginator` / `AsyncPage`.
- `ADMINS`/`MANAGERS` must become a list of email strings (no more `(name, addr)` tuples).
- `URLIZE_ASSUME_HTTPS` transitional setting, with default flip in Django 7.0.

### VCF/Genomics Horizon

- **VCF 4.5 is actively being drafted** in `samtools/hts-specs`. The draft introduces modified-base information at the genotype level (epigenetic/mod-base sequencing support). Still a draft — no action needed now, but relevant if MetaGap's user base begins handling ONT/PacBio modified-base calls.
- **VCF 4.4** is published and the current stable spec (some projects already emit it). MetaGap's pysam-based pipeline supports it transparently via htslib.
- Parser landscape unchanged: pysam (htslib wrapper) and cyvcf2 (Cython+htslib; ~6.9× faster than pysam) remain dominant. vcfpy (pure Python, fallback here) is slowest but most portable. If ingest throughput becomes a bottleneck, cyvcf2 is the proven upgrade path.
- **VCF-Zarr** (GigaScience 2025) remains a watch item for biobank-scale datasets.

### CI Gaps

Looking at `.github/workflows/ci.yml`:

1. **Branch mismatch (unchanged).** The workflow triggers on `push.branches: [main]`, but the repository's default branch is `master`. Direct pushes to `master` will **not** run CI. One-line fix: add `master` to the list (or rename the default branch).
2. **No pip caching.** Add `cache: 'pip'` to the `actions/setup-python@v5` step to cut install time.
3. **No linting.** No `ruff check`, `flake8`, `black --check`, or `mypy` step.
4. **No security scanning.** No `pip-audit`, `safety check`, or `bandit`. Given the Django CVE situation, this would have surfaced the 5.1 EOL months ago.
5. **`coverage` version not pinned.** `pip install -r requirements.txt coverage` installs whatever coverage happens to be latest — source of flaky reproducibility.
6. **Single-version test matrix.** Python 3.11 only; no forward-compat check against 3.12.
7. **No migrations check.** `python manage.py makemigrations --check` would catch drift between models and migrations.

**Bug in `get_or_create_sample_group` (lines 208-217):** The function calls `SampleGroup.objects.create(description=..., organization_profile=...)`. Neither field exists on `SampleGroup`: the model defines `comments` (not `description`) and `created_by` (not `organization_profile`). The function currently swallows the `TypeError` via a broad `except Exception: return None`, so its tests pass only because every call-site expects `None`. Either (a) fix the field names if the helper is intended to be used, (b) delete it, or (c) promote it to test-infrastructure under `app/tests/` and remove it from the production module.

### Test Quality Notes

`test_vcf_importer.py` has 968 lines but only ~2 `assertRaises`/ValidationError assertions — the bulk of the file is happy-path scenarios (metadata extraction, round-tripping, YAML-driven dispatch). Specific gaps:

- **`test_vcf_importer.py`** — No tests for: corrupt VCF body lines, invalid gzip/BGZF, pysam exceptions (`OSError`, `ValueError`, `NotImplementedError`), double-failure path (pysam → inflate → fallback all fail), or `ImporterConfigurationError` without an `OrganizationProfile`.
- **`test_vcf_database.py`** — No tests for: `IntegrityError` on duplicate sample-group name, `DataError` on out-of-range numeric metadata, `IntegrityError` on duplicate `(sample_group, chrom, pos, ref, alt)`.
- **`test_vcf_file_utils.py`** — Only one `ValidationError` assertion. No tests for: missing `#CHROM` header, truncated columns, `UnicodeDecodeError` branches, corrupted gzip stream.
- **`test_filters.py`** — No invalid-filter-value or empty-queryset assertions.
- **`test_views_sample_groups.py`** — No concurrent operations, cascade-delete edge cases, or form-validation error scenarios.

Because user-uploaded VCF files are the primary attack surface of this application, VCF-import error-path coverage is the single biggest code-health lever.

## Suggestions

1. **CRITICAL — Upgrade Django to 5.2.13 (LTS).** Flagged in six consecutive overnight reports. 5.1 is EOL with 12+ unpatched CVEs; 5.2 is the supported LTS (through April 2028), keeps Python 3.11 compatibility, and has no deprecation impact on MetaGap's patterns. Estimated effort: 1–2 hours for upgrade, test run, and regression check.

2. **Fix CI branch trigger.** `.github/workflows/ci.yml` triggers on `main` but the repo's default branch is `master`. Either rename the default branch or add `master` to the trigger list. One-line fix that enables CI for every push.

3. **Add error-path tests for the VCF import pipeline.** Start with the five highest-value cases: (a) corrupt `.gz` requiring the inflate-retry path, (b) double-failure path → generic validation error, (c) text-fallback missing `#CHROM`, (d) `IntegrityError` duplicate sample-group, (e) `DataError` on oversized metadata values. These are the gaps most likely to mask production regressions.

4. **Fix or remove `get_or_create_sample_group`.** The helper in `vcf_database.py:188` calls non-existent fields (`description`, `organization_profile`) and silently returns `None`. Either correct the field names (`comments`, `created_by`) or delete the helper and its tests; it is a latent footgun.

5. **Add `pip-audit` + `ruff check` to CI.** Two parallel jobs. `pip-audit` would have flagged the 5.1 EOL situation automatically. `ruff check --select E,F,W,I` is the cheapest linting baseline and doesn't require additional config.

6. **Upgrade `django-allauth` to 65.14.1+.** Contains the SAML IdP-SSO open-redirect fix. Low-risk patch upgrade — the bug only fires with SAML enabled, but keeping current closes the CVE cleanly.

7. **Pin `coverage` in CI.** Add a line `coverage==7.13.x` (or commit to a current patch level) in `.github/workflows/ci.yml` next to the `pip install` step.

8. **Commit or delete the three untracked overnight reports** (`2026-04-11.md`, `2026-04-12.md`, `2026-04-14.md`). They have been lingering in the working tree for days. A single `chore: batch overnight reports` commit would keep history clean without fabricating a per-day timeline.

9. **Consolidate metadata constants.** `vcf_metadata.py` still duplicates the YAML in module-level `METADATA_SECTION_MAP` / `METADATA_MODEL_MAP` / `METADATA_FIELD_ALIASES` / `SECTION_PRIMARY_FIELD`. Either remove them (and update any imports in `vcf_file_utils.py`) or regenerate them at module import from the `MetadataConfiguration`. Two sources of truth is a maintenance trap.

10. **Run `manage.py test` locally in an unsandboxed terminal and paste the coverage numbers into the next report.** Coverage has been unverified for six consecutive overnight reports; a single local run will re-ground the threshold claims.
