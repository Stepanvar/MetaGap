| `MetaGap/locale/ru/LC_MESSAGES/django.po` | 2 | 0 | 0 |
| `MetaGap/locale/en/LC_MESSAGES/django.po` | 2 | 2 | 0 |

The `en/` catalogs being almost entirely empty is expected — `gettext_lazy` is given English source strings, so Django falls back to the `msgid` when `msgstr` is empty. The 37 **fuzzy** entries in `app/locale/en/django.po` still matter though: `compilemessages` normally skips `#, fuzzy` entries, so any English string that was edited after translation memory was loaded is dropped and becomes `msgid` at runtime (harmless for English, but identifies rot in the extraction pipeline). The `3` untranslated in `ru` are real gaps.

## Research Findings

### Django Updates & Deprecations

Django 5.1 is **EOL since 2025-12-31** ([HeroDevs / endoflife.date](https://endoflife.date/django)). Django 5.2 is the current LTS (released 2025-04-02) and 6.0 is the current feature release ([5.2 release notes](https://docs.djangoproject.com/en/6.0/releases/5.2/)). For a Django 5.1 → 5.2 upgrade, this project's code is likely fine as-is because:

- `gettext_lazy`, `TextChoices`, `JSONField`, class-based views, `i18n_patterns`, and the signal hook in `app/signals.py` are all stable APIs.
- `app/filters.py` uses django-filter (not core Django) so QuerySet API changes shouldn't bite.
- No explicit use of `force_text`, `ugettext_*`, or `url()` removed APIs.

5.2 features worth adopting later:
- **Composite primary keys** — not applicable to our schema.
- **Automatic model imports in shell** — small DX win.
- **`AlterConstraint`** migration op — matters when we iterate on the `AlleleFrequency` unique constraint.
- `runserver` production-warning suppression via `DJANGO_RUNSERVER_HIDE_WARNING` — zero effort.

No deprecated APIs in use that I could find.

### VCF/Genomics Horizon

- **VCF 4.5 draft (Oct 2024)** has been published alongside 4.4 on samtools/hts-specs. Our importer claims no particular version — it parses `##`-prefixed lines and treats `SEQUENCING_PLATFORM`/`SAMPLE_GROUP`/etc. as custom header sections, so forward compatibility with 4.4/4.5 is largely about _new reserved keywords_ (e.g., modified-base annotations, haplotype linkage) and _structural-variant columns_. Our pipeline does not reject unknown INFO/FORMAT keys — it funnels them into `Info.additional` or `Format.additional` JSON — so we won't break on 4.5 files, but we also won't understand them.
- **pysam 0.23.3** wraps htslib 1.23.1 which handles 4.5 drafts; upgrading pysam is the cheapest way to stay current.
- **vcfpy** is essentially stalled upstream; if we ever depend on it for write-path features, that's a maintenance risk. Today it is in requirements.txt but no code imports it (see Unused Code).

### CI Gaps

Reading `.github/workflows/ci.yml`:

- **No lint step.** No `ruff`/`flake8`/`black --check`. Dead imports (`Tuple` in `vcf_file_utils.py` — see below) are not caught.
- **No type-check step.** `mypy` or `pyright` would have caught `get_or_create_sample_group` referencing non-existent `description=` / `organization_profile=` kwargs.
- **No dependency audit.** `pip-audit` or `safety` would flag the urllib3 2.2.3 CVE.
- **No secret-leak scan.** `gitleaks` or GitHub's native secret scanning.
- **No pytest job.** The pytest-based tests in seven `app/tests/*.py` files are silently skipped by `manage.py test` discovery.
- **Python version pinning is loose** — `python-version: '3.11'` with no minor pin. Fine today, but `actions/setup-python@v5` will drift.
- **`continue-on-error: true` on the test step** is intentional (to run coverage enforcement even on test failure) but also means a flaky test suite looks "mostly green" on the CI dashboard. Combine with `coverage --fail-under` so failed tests still fail the job end-to-end.
- **Duplicate coverage invocations** — the job runs `coverage report` three times (summary, MetagapUserCode include, app include). Collapse to one invocation with `--fail-under` rules in a tool config (`pyproject.toml` or `.coveragerc`) instead.

## Suggestions

Ranked by estimated value per engineering-hour:

1. **Upgrade Django 5.1.1 → 5.2 LTS (HIGH; hours).** 5.1 is EOL; no security fixes coming. `pip install "django~=5.2"`, run the test suite, bump the CI Python version pin to `3.11.x` with an upper bound, ship. Zero code changes expected based on the APIs this project uses.
2. **Wire pytest into CI (HIGH; ~1 day).** Add a `pytest` job that runs alongside `manage.py test`, or convert the seven pytest-style files to `django.test.TestCase` subclasses. Currently ~170 test functions never execute — this is not a theoretical risk: `test_vcf_database.py` has been asserting against the broken `get_or_create_sample_group` helper for months and nobody noticed. Once pytest runs, delete or fix the five dead helpers in `vcf_database.py` (one commit either way).
3. **Bump urllib3 ≥ 2.6.3 (HIGH; minutes).** CVE-2026-21441 DoS. Pin in `requirements.txt` and let `requests==2.32.3` keep its own constraint.
4. **Delete dead code (MEDIUM; hour).** In one PR: (a) remove `convert_to_python_type`, `extract_info_field_metadata`, `extract_format_field_metadata`, `extract_contig_field_metadata`, `get_or_create_sample_group` and their `__all__` entries in `vcf_database.py`; (b) remove the hardcoded `METADATA_MODEL_MAP`/`METADATA_FIELD_ALIASES`/`SECTION_PRIMARY_FIELD` from `vcf_metadata.py` and rewire `vcf_file_utils.py` to `load_metadata_configuration().section_map`; (c) delete `MetaGap/_po_count.py`; (d) drop `beautifulsoup4` from `requirements.txt` (with `soupsieve`) if nothing imports it.
5. **Add a lint + type gate to CI (MEDIUM; ~½ day).** Start with `ruff check` + `ruff format --check`; it will catch the missing `Tuple` import in `vcf_file_utils.py` and the bare `except Exception` pattern in `get_or_create_sample_group`. Add `mypy --strict app/services/` next — small blast radius.
6. **Add `pip-audit` to CI (LOW-MEDIUM; 30 min).** `pip-audit -r requirements.txt` flags the urllib3 CVE above and future ones automatically. Gate at `--strict` with an allowlist for known-accepted findings.
7. **Bump pysam 0.22.1 → 0.23.3 (LOW; ~1 hour).** Better I/O exception messages land in the fallback warning `"Could not parse VCF metadata with pysam: …"`, which directly improves user diagnostics for the 9+ test cases that currently exercise that path.
8. **Bump django-allauth 65.0.1 → 65.16.0 (LOW; minutes).** SAML SSO is unused today but future-proofs + picks up minor UX fixes; bundle with the Django 5.2 upgrade PR.
